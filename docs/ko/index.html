Proof Engine

화면에 보이는 모든 것이 수학 함수의 출력인 Rust 렌더링 엔진입니다. 글리프와 파티클을 미분방정식과 힘의 장으로 움직이고 HDR로 그립니다.

cargo add proof-engine
Windows용 데모 다운로드 macOS 및 Linux 소스 코드

그림 1sky 예제의 16:20부터 해 질 녘까지. PROOF_SHOT으로 프레임마다 캡처해 정방향과 역방향으로 재생했습니다. 이 하늘의 모든 셀이 하나의 산란 적분입니다.

Nishita 하늘

해를 끌어 보세요.

하늘은 120 × 56개의 셀로 이루어져 있습니다. 매 프레임마다 각 셀에 대해 nishita_sky::compute_sky_color가 시선 방향 광선과, 태양을 향하는 또 다른 광선을 따라 레일리 산란과 미 산란(단일 산란)을 적분합니다.

그라데이션은 어디에도 직접 칠하지 않았습니다. 오후 세 시의 파란색, 해 질 녘의 주황색 띠, 그 뒤의 짙은 청록색은 모두 태양 위치만 다른 같은 적분입니다. 산맥은 사인 함수의 합이며, 지평선 바로 위 하늘의 빛을 받습니다.

스트레인지 어트랙터

점 사만 개, 방정식 하나.

dx/dt = 10 (y − x)
dy/dt = x (28 − z) − y
dz/dt = x y − 8⁄3 z

각 점은 하나의 상태이며, 엔진 자체의 RK4 스텝으로 매 프레임 진행됩니다. 두 날개는 누가 그린 것이 아니라 방정식이 점들을 보내는 곳입니다. 같은 모듈에 Rossler, Chen, Halvorsen, Aizawa, Thomas, Dadras 등이 들어 있으며, 어느 것이든 힘의 장을 구동할 수 있습니다.

examples/lorenz.rs
for p in points.iter_mut() {
    for _ in 0..SUBSTEPS {
        *p = rk4_step(lorenz, *p, h);
    }
}

빠른 시작

명령어 두 줄이면 실행됩니다.

stable Rust와 OpenGL 3.3을 지원하는 GPU가 필요합니다. Windows와 macOS에서는 그 밖에 필요한 것이 없습니다. Linux에서는 먼저 ALSA 헤더를 설치하세요: sudo apt install libasound2-dev pkg-config.

01데모 실행

첫 빌드는 엔진 전체를 컴파일하므로 몇 분 걸립니다. --release를 사용하세요. 데모는 프레임마다 수만 개의 파티클을 시뮬레이션합니다.

shell
git clone https://gitlab.com/mattbusel/proof-engine.git
cd proof-engine
cargo run --release --example sky
cargo run --release --example lorenz

02라이브러리로 사용하기

5,000개의 점이 짧은 선 하나에서 출발해 로렌츠 방정식을 따라 움직입니다. 저장소에도 examples/quickstart.rs로 들어 있습니다.

shell
cargo new lorenz-demo && cd lorenz-demo
cargo add proof-engine
src/main.rs
use proof_engine::math::attractors::rk4_step;
use proof_engine::prelude::*;
use proof_engine::render::ui_layer::UiParticle;

fn main() {
    let mut engine = ProofEngine::new(EngineConfig::default());

    // 5,000 points in a line 2 units long, each 0.0004 from the next.
    let mut points: Vec<Vec3> = (0..5000)
        .map(|i| Vec3::new(1.0 + i as f32 * 4e-4, 1.0, 1.0))
        .collect();

    engine.run_ui(move |engine, dt| {
        // Advance every point along the Lorenz equations.
        for p in points.iter_mut() {
            *p = rk4_step(AttractorType::Lorenz, *p, dt);
        }
        // Draw them: x across, z up, centred in the window.
        let (w, h) = engine.render_size();
        let (cx, cy, s) = (w as f32 / 2.0, h as f32 / 2.0, h as f32 / 60.0);
        let color = Vec4::new(0.5, 1.2, 1.6, 1.0);
        let dots = points
            .iter()
            .map(|p| UiParticle::new(cx + p.x * s, cy - (p.z - 25.0) * s, 3.0, 3.0, '●', color))
            .collect();
        engine.ui.draw_particles(dots);
    });
}

cargo run --release로 실행하세요. 십 초 정도는 점들이 한 줄기로 함께 움직이다가, 이후 카오스가 이들을 떼어 놓아 나비 모양이 됩니다.

구성 요소

먼저 수학, 그다음 빛.

math

함수가 곧 애니메이션

어트랙터, 펄린 노이즈, 로지스틱 맵, 콜라츠, 리사주, 망델브로 탈출, 스프링. 어떤 글리프든 위치나 색을 구동하는 life_function을 가질 수 있습니다.

math::fields

조합 가능한 힘의 장

중력, 소용돌이, 전자기, 스트레인지 어트랙터, 충격파, 조석, 흐름, 쌍극자. 감쇠는 선형, 역제곱, 지수, 가우시안 중에서 고를 수 있습니다.

entity

파티클로 만든 몸체

엔티티는 응집력으로 묶인 글리프 덩어리입니다. 결합 강도가 HP를 따르므로, 공격을 받으면 애니메이션을 재생하는 대신 실제로 물질이 떨어져 나갑니다.

render

HDR 파이프라인

반정밀도 씬 버퍼, 블룸 피라미드, ACES, 렌즈 효과, 빛줄기, 물질이 드리우는 그림자, 그레인과 디더링. 상시 파라미터는 모두 RenderConfig의 필드입니다.

physics · audio

시뮬레이션과 사운드

SAT 기반 강체, 소프트 바디, 오일러 방식 유체. FM, 필터, 드라이브, 리버브를 갖춘 48 kHz 합성. 소리는 샘플이 아니라 합성으로 만듭니다.

worldgen · scripting

모든 것을 절차적으로

판 구조, 침식, 기후, 강, 정착지와 역사, 로트카-볼테라와 SIR 생태 모델, 클로저를 지원하는 바이트코드 VM.

그림 4수학이 프레임이 되는 과정. 실제 로렌츠 적분 결과를 예제 자체의 팔레트로 그렸습니다.

그림 5PROOF_HIDDEN=1 PROOF_SHOT으로 같은 프레임을 GPU에서 세 번 읽어 오면서 RenderConfig에서 블룸, 잔상, 톤 매핑을 껐습니다.

그림 6매 프레임 GPU에서 실행되는 과정. 화면 공간의 물질로 그린 게임은 전체에 블룸, 그레이딩, 그레인이 적용되고, 그 위에 읽기 쉬운 HUD가 얹힙니다.

예제보이는 것
sky산맥 위의 하루. 하늘의 모든 셀이 Nishita 산란 적분입니다. Space로 일시정지, 위/아래 키로 속도 조절.

galaxy약 3,000개의 글리프가 네 개의 나선팔 위에서 각자의 궤도를 돌고, 뜨거운 중심부와 떠다니는 성운 먼지가 있습니다.
strange_attractorsLorenz, Rossler, Chen, Halvorsen, Aizawa, Thomas, Dadras를 나란히, 각각 1,500개의 점. Space로 일시정지.
math_rain수학 기호로 된 디지털 비. 속도는 사인 함수에서, 깜빡임은 로지스틱 맵에서.
quickstart위의 프로그램. 5,000개의 점이 카오스에 의해 찢겨 로렌츠 나비가 됩니다.
convergence카메라가 주위를 도는 경기장에서 싸우는, 파티클로 만든 두 전투원. 공격을 받으면 물질이 떨어져 나갑니다.
supernova별이 맥동하고 붕괴하고 폭발한 뒤 로렌츠 성운으로 자리 잡습니다.
hello_glyph가장 작은 프로그램. 숨 쉬는 @ 하나와 중력장.
colossusGPU 밀도 엔티티: 본 열여섯 개에서 나오는 수백만 개의 파티클. 고성능 GPU가 필요합니다.

캡처

엔진이 직접 만든 프레임을 녹화하세요.

Proof Engine으로 만든 프로그램이라면 코드를 바꾸지 않고도 자기 프레임을 기록할 수 있습니다. 후처리를 마친 화면을 GPU에서 바로 읽어 옵니다. PROOF_HIDDEN=1을 쓰면 창이 보이지 않고 포커스도 가져가지 않으므로, 컴퓨터를 쓰는 동안에도 실행됩니다.

이 페이지의 모든 데모 프레임과 영상은 이렇게 기록했습니다.

shell
PROOF_HIDDEN=1 PROOF_FIXED_DT=60 \
PROOF_SHOT='frames/f_{n}.bmp' PROOF_SHOT_AT=560 \
PROOF_SHOT_EVERY=2 PROOF_SHOT_COUNT=240 \
cargo run --release --example sky

PROOF_FIXED_DT는 시뮬레이션을 고정 간격으로 진행하므로, 각 프레임 캡처에 시간이 얼마나 걸리든 시퀀스가 실제 속도로 재생됩니다. 크기는 PROOF_WINDOW=1920x1080으로 정합니다.
